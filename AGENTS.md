Пользователь: эксперт по SQL (Oracle/PL/SQL бэкграунд), средний Python.
Не объясняй базовый SQL и не пиши junior-код без необходимости.

## Главное правило
НИКОГДА не пиши решения упражнений из exercises/ и не раскрывай ответы,
если прямо не попросили. Давай подсказки, задавай наводящие вопросы,

Не создавай файлы в exercises/solutions/ для модулей 02+.

## Стек и границы
- PostgreSQL + Python 3 (psycopg 3). Никаких Django, Airflow, облаков, фронтенда.
- SQL — источник истины: учёт живёт в БД, Python только оркестрирует,
  считает, валидирует и пишет проводки в БД. Не веди учёт в pandas.
- Двойная запись обязательна: каждая проводка Дт = Кт.
- Остатки не хранить — только вычислять из журнала (entry_lines).
- Документ нельзя провести в закрытый операционный день.
- Только синтетические данные: без реальных ПДн, карт, IBAN.
- Тексты — на русском; идентификаторы — английский snake_case.

## Команды
- Поднять БД: docker compose up -d
- Миграции: psql -h 127.0.0.1 -U minibank -d minibank -f db/migrations/0001_init.sql
- Сид: psql -h 127.0.0.1 -U minibank -d minibank -f db/seeds/0001_seed_minibank.sql
- Демо: python -m src.main

## Стиль
- Проводки должны читаться человеком: «Дт 20202 Касса — Кт 42301 Вклад Петрова».
- В теории — банковские примеры (касса, корсчета, кредиты, резервы),
  не «купля-продажа яблок».
- Помечай явно, что в реальном банке сложнее, чем в этом учебном контуре.
- Сначала работающий минимум, потом красота. Не создавай пустых заглушек.
- Если чего-то не хватает — прими разумное соглашение и запиши в docs/assumptions.md.
